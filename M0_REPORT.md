## Commands implemented

Run from `/root/projects/motion-foundry`:

```sh
npm ci --ignore-scripts
npm test
node dist/src/cli.js --help
node dist/src/cli.js render fixtures/m0-overflow/scene.json --out runs/m0-final --no-cache
# Repeat the same render command for the second uncached attempt.
node dist/src/cli.js validate <attempt_directory>
node dist/src/cli.js probe-reviewer runs/m0-final/probe
node dist/src/cli.js repair-loop fixtures/m0-overflow/scene.json --out runs/m0-final --mock --max-attempts 3
node dist/src/cli.js verify runs/m0-final
```

The package also exposes the CLI through `npm run foundry -- ...`. A plain overflowing fixture deliberately fails validation; a mock PASS is never LIVE. CLI hard failures exit nonzero. Each invocation has a unique attempt directory, including cache reuse. Loop/probe outputs refuse overwrites.

## Interpretation and limitations

- `required_content.v1` is fixture-only for M0. Baseline counts use fully opaque/displayed word frames, including originally clipped words, so overflow cannot create a zero-count loophole. Candidate words must meet those counts inside the safe area.
- Ordinary blank/visibility-flash findings can only WARN. Explicit scene contracts can FAIL based on tagged visible geometry. This is not a pixel-level blankness or universal artistic-quality classifier.
- No audio is present; audio analysis is NOT_RUN. Optional MP4, luma-jump and collision analysis are not implemented. No creative-quality claim is made.
- No live reviewer adapter or canary invocation was invented. Transport remains unverified and live review is blocked. Unknown authentication/spend risk is never treated as subscription inclusion.
- Evidence files are hash checked and core validators recomputed by verify. These hashes detect modification; they are not cryptographic signatures against an attacker rewriting an entire run and its hashes.

## Determinism history, environment and blockers

A later full-suite run exposed a real pixel mismatch after the first milestone checks had passed: frame 156 differed at 39 shape-edge pixels despite identical bounds. Turning off automatic 3D transforms alone did not resolve it; a subsequent run differed at frame 1. These failures were not accepted, and the prior attempt directories remain intact. See [the retained diagnostic](runs/observed-nondeterminism.json).

The final renderer disables partial rasterization and pins compositor/Skia settings, uses pinned Inter for evidence labels, and disables GSAP automatic 3D transforms and lazy updates. The final 41-test suite and the separate CLI uncached pair both passed exact comparison. No pixel tolerance, validator relaxation, text rewrite or fixture simplification was used. Flags were checked against [Google Chrome's tooling documentation](https://github.com/GoogleChrome/chrome-launcher/blob/main/docs/chrome-flags-for-tools.md).

Environment: Node v22.14.0; Chromium 131.0.6778.204; Playwright 1.48.2; GSAP 3.12.5; Inter package 5.1.0. ffmpeg is absent; no MP4 or audio result is claimed. Rendering is 1080x1920 logical, 540x960 output, 30/1 fps, frames [0,270). Cross-machine determinism is not claimed.

The live-review blocker is the absence of a subscription CLI with verified image transport. No canary/model call was made. Installing a tool and proving subscription authentication, zero-spend execution and attachment transport are prerequisites for a later live run; this run stops at milestone 7 as instructed.
